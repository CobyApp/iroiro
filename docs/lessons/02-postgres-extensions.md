# 02. Postgres Extension

## 왜 알아야 하는가

Postgres는 코어를 작게 유지하고 부가 기능을 **떼었다 붙일 수 있는 모듈**로 분리해서 배포합니다. UUID 생성, 지리정보, 벡터 검색, 암호화 같은 기능들이 모두 extension으로 들어옵니다. Supabase는 이런 확장들을 미리 깔아두고 토글로 켜는 형태로 노출합니다.

## 핵심 개념

extension 하나가 추가할 수 있는 것:

| 종류 | 예 |
|---|---|
| **함수** | `gen_random_uuid()`, `digest()` (pgcrypto) |
| **데이터 타입** | `geometry`, `geography` (postgis), `vector` (pgvector) |
| **연산자** | `<->` (벡터 거리), `%` (pg_trgm 유사도) |
| **인덱스 종류** | `GIST`, `GIN`, `ivfflat` 등 새 타입에 적용 |
| **시스템 뷰** | `pg_stat_statements` 뷰 |
| **백그라운드 워커** | `pg_cron` 같은 스케줄러 |

라이브러리 import보다 깊게 — **DB 엔진 동작 자체를 확장**합니다. 인덱스 종류·연산자까지 추가할 수 있다는 게 일반 라이브러리와의 결정적 차이.

## 문법

```sql
-- 활성화 (이미 깔려 있으면 통과)
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- 특정 스키마에 설치
CREATE EXTENSION pgcrypto SCHEMA extensions;

-- 비활성화 (의존 객체 있으면 CASCADE 필요)
DROP EXTENSION pgcrypto;
DROP EXTENSION pgcrypto CASCADE;
```

`CREATE EXTENSION`은 "이미 OS·클러스터에 *설치된* 확장을 *현재 DB에 등록*" 합니다. 외부에서 다운받지 않습니다. 패키지 자체는 OS 패키지(예: `apt install postgresql-contrib`)나 Postgres 빌드에 포함되어 있어야 합니다.

권한: 보통 `CREATE EXTENSION`은 superuser 또는 그에 준하는 권한 필요. Supabase는 대시보드 토글로 안전하게 노출.

## 자주 쓰는 확장

| 확장 | 용도 | Supabase 기본 |
|---|---|---|
| `pgcrypto` | 암호화 함수, `gen_random_uuid()` | ✅ 활성 |
| `uuid-ossp` | UUID v1/v3/v5 (v4만 필요하면 pgcrypto로 충분) | ✅ |
| `pg_trgm` | 유사어 검색, `LIKE`/`ILIKE` 가속 | ✅ |
| `pgcrypto` | 해시·HMAC·대칭 암호화 | ✅ |
| `postgis` | 지리정보 (위치, 거리, 폴리곤) | 🟡 토글 |
| `vector` (pgvector) | 임베딩 벡터 검색, 시맨틱 서치 | 🟡 토글 |
| `pg_stat_statements` | 쿼리 통계 모니터링 | ✅ |
| `pg_cron` | DB 안에서 스케줄 작업 | 🟡 토글 |

## 조회·관리

```sql
-- 이 DB에 켜진 확장 목록
SELECT extname, extversion FROM pg_extension;

-- 사용 가능한(설치되어 있지만 안 켜진) 확장 목록
SELECT * FROM pg_available_extensions WHERE installed_version IS NULL;

-- 특정 확장이 추가한 객체 보기
SELECT
    pg_describe_object(classid, objid, objsubid) AS object
FROM pg_depend
WHERE refobjid = (SELECT oid FROM pg_extension WHERE extname = 'pgcrypto')
  AND deptype = 'e';
```

## Supabase 컨텍스트

Supabase 프로젝트는 자주 쓰는 확장을 **미리 활성화**해 둡니다 (`pgcrypto`, `pg_trgm`, `pg_stat_statements` 등). 대시보드에서 추가 토글이 가능: **Database → Extensions**.

확장을 마이그레이션에 명시하면 좋은 점:
- 다른 환경(로컬 Postgres, CI, 다른 팀원의 개발 DB)에서 같은 마이그레이션을 돌릴 때 안 깨짐
- 의존성이 코드에 명문화 — 뭘 쓰는지 한눈에 보임

명시 안 하면 Supabase에선 동작하지만 순정 Postgres에선 함수가 없다는 에러.

## 이 프로젝트의 결정

현재 (2026-05-09 기준) 사용하는 확장 **없음**.

처음에는 `gen_random_uuid()`를 PK 디폴트로 쓰려고 `CREATE EXTENSION IF NOT EXISTS pgcrypto`를 넣었으나, PK를 `BIGINT GENERATED BY DEFAULT AS IDENTITY`로 변경하면서 함께 제거했습니다 ([03. Primary Key 전략](./03-primary-key-strategy.md) 참고).

향후 추가 가능성:
- **`pg_trgm`** — 상품명·그룹명 유사어 검색 (예: 오타 허용 검색)
- **`vector`** — 굿즈 이미지 임베딩 기반 시맨틱 검색
- **`postgis`** — 오프라인 매장 위치 검색 (해당 기능 추가 시)

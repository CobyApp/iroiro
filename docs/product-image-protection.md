# 고객용 상품 이미지 보호

## 적용 경계

고객 화면의 모든 트레카 이미지는 R2 원본 주소가 아니라 다음 same-origin 경로를 사용한다.

- 개별 앞·뒷면: `/media/product-photos/{photoId}/{signature}`
- 대표 이미지: `/media/product-thumbnails/{productId}/{signature}`

서명은 서버의 R2 secret에서 도메인 분리한 HMAC으로 생성한다. ID나 서명이 변조되면 DB·R2를 조회하기 전에 404로 응답한다. 정상 요청도 원본을 그대로 전달하지 않고 다음 순서로 처리한다.

1. S3 API 서명 GET으로 R2 원본 읽기
2. 입력 20MB·4천만 픽셀 상한 검사
3. 최대 1100×1500으로 축소
4. 이로이로 워드마크 반복 합성
5. 품질 82 WebP로 재인코딩
6. same-origin CORP·nosniff·inline 응답 및 CDN 캐시

## 운영에서 반드시 닫아야 하는 우회 경로

애플리케이션만 배포하고 R2 공개 원본 URL을 그대로 두면 과거에 알려진 키나 추측한 키로 원본에 접근할 수 있다. Cloudflare R2 운영 설정도 함께 적용해야 보호 경계가 완성된다.

1. R2의 **Public Development URL (`r2.dev`)을 비활성화**한다.
2. 상품·공지 등이 같은 공개 버킷을 공유하는 동안에는 공개 커스텀 도메인 WAF에서 경로가 `products/original/`로 시작하는 요청을 차단한다.
3. 앱 서버는 공개 도메인이 아니라 `R2_ENDPOINT/R2_BUCKET` S3 API와 access key로 원본을 읽는다.
4. 장기적으로 상품 원본 버킷을 공지·배너 공개 버킷과 분리하고 상품 버킷에는 공개 도메인을 연결하지 않는다.
5. 기존 CDN에 원본 상품 응답이 캐시되어 있다면 WAF 적용과 함께 해당 prefix를 purge한다.

## 한계

브라우저에 표시된 픽셀은 스크린샷이나 촬영으로 100% 회수 방지할 수 없다. 이 구현의 목표는 원본 파일·원본 해상도·무워터마크 이미지를 고객 경로로 제공하지 않고, 캡처된 결과에도 반복 워터마크가 남도록 만드는 것이다. CSS 오버레이나 우클릭 차단만을 보안 경계로 간주하지 않는다.

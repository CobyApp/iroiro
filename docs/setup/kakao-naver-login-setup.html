카카오·네이버 소셜 로그인 설정 가이드

oshikore-web 자체 인증(OAuth) — 콘솔 등록부터 로컬 테스트까지

최종 업데이트: 2026-06-14 · 대상: 운영자/개발자 · 관련 코드: modules/auth/

이 문서는

카카오·네이버 로그인은 각 제공자 콘솔에 앱을 등록하고 키를 발급받아야만 동작합니다. 코드는 이미 구현돼 있으니, 이 문서의 체크리스트대로 외부 등록 + 환경변수만 채우면 됩니다.

큰 그림 — 로그인 한 번에 일어나는 일 /login 버튼 → /api/auth/{provider}(우리 서버) → 카카오·네이버 동의 화면 → /api/auth/{provider}/callback(우리 서버, 계정·세션 생성) → 로그인 완료. 소셜 로그인은 로그인 = 회원가입이라 첫 로그인 시 계정이 자동 생성됩니다.
사업자등록증이 필요한가요? — 아니요 (둘 다 개인 개발자로 가능) 카카오·네이버 로그인은 사업자 없이 개인(본인인증)만으로 정식 오픈까지 가능합니다. 카카오는 이메일을 받으려면 비즈 앱이 필요하지만, 사업자 대신 본인인증(개인 개발자 비즈 앱)으로 대체됩니다(아래 ① 참고). 네이버는 검수까지 포함해 사업자 정보가 필요 없습니다(아래 ② 참고). 사업자는 "있으면 편한" 요소일 뿐 로그인의 필수 조건은 아닙니다.

K 카카오 앱 등록

콘솔: developers.kakao.com

  1. 애플리케이션 추가 — [내 애플리케이션] → [애플리케이션 추가하기]. 앱 이름 입력(사업자명은 개인 개발자는 선택).
  2. REST API 키 복사 — [앱 설정] → [앱 키] → REST API 키 → 환경변수 KAKAO_REST_API_KEY.
  3. 카카오 로그인 활성화 — [제품 설정] → [카카오 로그인] → 활성화 설정 ON.
  4. Redirect URI 등록 — [카카오 로그인] → Redirect URI에 아래를 정확히 추가. 
    http://localhost:3000/api/auth/kakao/callback
    운영 도메인이 있으면 https://{도메인}/api/auth/kakao/callback도 함께 등록.
  5. Client Secret 발급 — [앱 설정] → [앱 키] → REST API 키를 클릭하면 그 안에서 클라이언트 시크릿 코드를 확인/생성합니다(2번에서 복사한 그 REST API 키 화면 내부). 값을 KAKAO_CLIENT_SECRET에 입력.
    활성화 상태와 env 값을 일치시키세요 개편된 콘솔은 클라이언트 시크릿이 활성화('사용')된 채로 자동 추가되곤 합니다. 활성화 상태면 카카오가 토큰 교환 때 client_secret을 요구하므로 KAKAO_CLIENT_SECRET을 반드시 채워야 합니다(비우면 oauth_failed). 즉 "콘솔 활성화 ↔ env 값"은 한 몸 — 둘 다 켜거나 둘 다 끄세요. (구버전 콘솔이면 [제품 설정] → [카카오 로그인] → [보안]에 같은 항목이 있습니다.)
  6. 동의항목 설정 — [카카오 로그인] → [동의항목]에서 닉네임(profile_nickname) 사용 설정.
    이메일은 비즈니스 앱(Biz App)에서만 카카오계정(이메일)(account_email)은 비즈 앱 전환 후에만 받을 수 있습니다. 그전까지는 이메일이 비어 있는 채로 가입됩니다(정상). 이메일까지 받으려면 비즈 앱 전환 후 KAKAO_SCOPE="profile_nickname,account_email"로 설정하세요.
    사업자등록증 없이도 이메일을 받을 수 있습니다 비즈 앱 전환은 두 경로입니다 — ① 일반 비즈 앱(사업자등록번호 입력), ② 개인 개발자 비즈 앱: 사업자 없이 앱 소유자 본인인증([계정 설정] → [본인인증]) + 카카오비즈니스 약관 동의만으로 [앱] → [일반] → [비즈니스 정보]에서 전환합니다. 개인 개발자 비즈 앱도 이메일 필수 동의가 가능하므로 이메일 때문에 사업자를 낼 필요는 없습니다. (단, 개인 개발자 비즈 앱은 비즈니스 채널 연결 불가 — 필요 시 일반 비즈 앱으로 전환.)
왜 scope를 명시해야 하나 카카오는 동의항목을 콘솔에 켜두는 것만으론 부족하고, 로그인 요청에 scope로 명시해야 닉네임·이메일을 받습니다. 코드가 자동으로 profile_nickname(또는 KAKAO_SCOPE)을 보냅니다.

N 네이버 앱 등록

콘솔: developers.naver.com/apps

  1. 애플리케이션 등록 — [Application] → [애플리케이션 등록]. 앱 이름 입력.
  2. 사용 API 선택 — 네이버 로그인 선택.
  3. 제공 정보 선택 — 필요한 항목 체크: 이름·이메일·별명(닉네임) 등. (앱이 사용자에게 요청할 정보)
  4. 서비스 환경 + Callback URL — [환경 추가] → PC웹. 서비스 URL과 Callback URL 등록. 
    서비스 URL : http://localhost:3000
Callback URL: http://localhost:3000/api/auth/naver/callback
    운영 도메인이 있으면 https://{도메인} / https://{도메인}/api/auth/naver/callback도 등록.
  5. Client ID / Secret 확인 — 등록 후 [개요]에서 NAVER_CLIENT_ID / NAVER_CLIENT_SECRET 복사.
  6. 검수 요청 — 본인(등록 개발자) 외 일반 사용자도 로그인하려면 [검수] 요청이 필요합니다.
    검수 전에는 등록된 개발자 계정만 로그인됩니다 개발·테스트 단계에선 앱 소유자 네이버 계정으로만 로그인이 됩니다. 정식 오픈 전 검수를 통과해야 모든 사용자가 로그인할 수 있습니다(제공 정보 심사 포함). 검수에 사업자등록증은 필요 없으며, 개인 서비스도 통과할 수 있습니다(필수 수집 정보를 이메일·별명·프로필 사진 정도로 최소화하면 유리).
    네이버 검수 통과 요건 — 신청 전 갖춰두면 한 번에 통과 네이버는 "꼭 필요한 정보만 받는지"와 "로그인 UI가 실제로 붙어 있는지"를 심사합니다. 신청 전 아래를 준비하세요:
    • 로그인·회원가입 화면에 네이버 공식 버튼 디자인으로 로그인 버튼을 실제 노출
    • 제공 정보(필수 수집) 최소화 — 특별한 사유가 없으면 이메일·별명·프로필 사진만 필수 체크. 휴대전화번호 등 과한 항목은 사용 목적 소명이 필요하며 거절 사유 1순위
    • 회원가입 프로세스 화면 캡처 업로드
    • 네이버 로그인이 가능한 테스트 아이디 등록
    신청 위치 — 네이버 개발자센터 → [Application] → [내 애플리케이션] → 해당 앱 → 개발 상태 항목의 검수 요청 버튼.
    실무 팁 — ① 검수 전에도 멤버(매니저)·테스트 계정을 추가하면 그 계정들은 바로 로그인 테스트가 됩니다(팀 내부 확인용). ② 심사에 영업일이 소요되니 정식 오픈 일정에 여유를 두세요.

④ Redirect / Callback URI 레퍼런스

콘솔에 등록하는 URI는 코드의 콜백 경로와 한 글자도 다르면 안 됩니다(가장 흔한 실패 원인).

제공자로컬운영
카카오http://localhost:3000/api/auth/kakao/callbackhttps://{도메인}/api/auth/kakao/callback
네이버http://localhost:3000/api/auth/naver/callbackhttps://{도메인}/api/auth/naver/callback
자주 틀리는 부분 ① http vs https 혼동, ② APP_URL 끝 슬래시(→ //api), ③ 포트 누락, ④ 로컬·운영 URI를 둘 다 등록 안 함. 콘솔 등록값과 APP_URL 기준 생성값이 정확히 같아야 합니다.

⑤ 로컬 테스트

세션이 DB에 저장되므로 실 DB가 필요합니다(npm run dev mock 모드로는 로그인 불가).

npm run services:up      # supabase + docker(MinIO) 기동
npm run db:reset         # 마이그레이션 적용(init_catalog, init_account)
npm run db:generate      # Prisma 클라이언트 생성
# .env.local에 DATABASE_URL + 카카오/네이버 키 채우기 (위 ③)
npm run dev:all          # USE_MOCK_DATA=false 로 개발 서버
  • http://localhost:3000/login 접속 → 카카오/네이버 버튼이 보인다
  • 카카오 버튼 → 카카오 동의 화면 → 승인 → /로 돌아오고 로그인됨
  • 네이버 버튼 → (등록 개발자 계정으로) 동의 → 로그인됨
  • DB account·account_identity·account_session에 행이 생긴다 (npm run db:studio로 확인)
PKCE 라이브 확인(카카오) 현재 카카오에 PKCE(code_challenge)를 함께 보냅니다(보안 강화). 첫 로그인이 정상 동작하면 그대로 두면 되고, 혹시 카카오가 거부하면 modules/auth/lib/oauth/kakao.ts의 usesPkce: true → false 한 줄만 바꾸면 됩니다.

⑥ 운영(배포) 체크리스트

  • APP_URL을 운영 도메인(https)으로 설정
  • 카카오·네이버 콘솔에 운영 Redirect/Callback URI 등록
  • 네이버 검수 통과(일반 사용자 로그인 가능 상태)
  • 이메일이 필요하면 카카오 비즈 앱 전환 + KAKAO_SCOPE에 account_email 추가
  • 운영 DATABASE_URL은 커넥션 풀러(Supavisor 등) 경유로 설정(서버리스)
  • 비밀키는 배포 플랫폼의 환경변수/시크릿으로 주입(코드·git 금지)
  • 로그인 버튼은 정식 배포 전 카카오·네이버 공식 버튼 가이드 준수

⑧ 설계 · 아키텍처

자체 인증(Supabase Auth 미사용) + DB 세션 방식입니다. 제공자에서 받은 신원으로 account·account_identity를 만들거나 연결하고, account_session(해시 토큰)으로 세션을 발급해 httpOnly 쿠키로 로그인 상태를 유지합니다.

설계 배경 초기엔 Supabase Auth(auth.users) 기반을 검토했으나, "어떤 Postgres에서도 동작하는 자체 인증(DB 세션)"으로 방향을 바꿨습니다. 그래서 auth.users에 의존하지 않고 앱이 직접 account 테이블과 세션을 소유합니다.

로그인 한 사이클

  1. 시작 — /login 버튼 → GET /api/auth/{provider}(우리 서버). state(CSRF)와 PKCE(카카오) 값을 쿠키에 심고 제공자 인증 페이지로 302.
  2. 동의 — 제공자 화면에서 사용자가 승인.
  3. 콜백 — 제공자가 ?code&state로 GET /api/auth/{provider}/callback(Node)로 리다이렉트. state 검증 → code를 토큰으로 교환 → 프로필 조회 → account 찾기/생성 + account_identity 연결 → account_session 발급(해시 저장) → 세션 쿠키 설정 → /로 302.
  4. 이후 요청 — DAL이 쿠키의 토큰 해시로 account_session 행을 조회해 로그인 상태를 확인(요청당 1회 캐시).

현재는 소셜 로그인 + 세션까지 구현돼 있습니다. 아래는 미구현(후속) 항목입니다.

  1. 전화 인증 온보딩 — 전화번호가 가입 필수. OAuth 직후 phone_number_verified_at = NULL(미완료) 상태이며, 콜백 TODO 지점에서 /onboarding/phone로 유도해야 함. SMS 게이트웨이(솔라피/알리고)+발신번호 사전등록(영업일 소요)이 외부 선결과제.
  2. 계정 연결/병합 — 현재 신원당 1계정. 같은 사람이 카카오·네이버로 각각 로그인하면 계정이 2개가 됨. 이메일/전화 기반 병합은 후속.
  3. 동의(consent) 수집 — 가입 시 약관·개인정보·만14세 필수 동의 + 마케팅 선택 동의 저장소 추가.
  4. Proxy 전환 — middleware.ts(Edge)를 proxy.ts(Node)로 옮기고 보호 경로 사전 체크 추가. 현재 admin 게이트는 임시 Basic Auth.
  5. app 롤 전환 — DB 접속을 postgres→app으로 바꿔 RLS 활성화(현재는 정의만 돼 있고 우회 중).
  6. 브랜드 자산 — 로그인 버튼을 카카오·네이버 공식 버튼 가이드에 맞춰 정식화.
  7. 레이트리밋·남용 방어 — 로그인/콜백 rate limit.
